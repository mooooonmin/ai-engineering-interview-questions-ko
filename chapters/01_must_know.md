AI 엔지니어링 면접에서 거의 항상 나오는 6가지 핵심 개념입니다. 각 개념을 한두 문장으로 정의하고, 서로 어떻게 연결되는지 설명할 수 있어야 합니다.

<details>
<summary><b>Q1. LLM</b></summary>

**대규모 언어 모델(Large Language Model)** 은 방대한 텍스트로 학습해 "다음 토큰"을 예측하는 신경망입니다. 대부분 트랜스포머(Transformer) 디코더 구조를 사용하며, 수십억~수천억 개의 파라미터를 가집니다.

- **동작 방식:** 입력 텍스트를 토큰으로 나눈 뒤, 지금까지의 토큰을 보고 다음 토큰의 확률 분포를 계산합니다. 그 분포에서 토큰 하나를 고르고, 다시 입력에 붙여 같은 과정을 반복합니다(자기회귀 생성).
- **학습 단계:**
  1. 사전 학습(pre-training): 인터넷 규모 텍스트로 다음 토큰 예측을 학습해 언어와 세상 지식을 익힙니다.
  2. 지시 튜닝(SFT): 질문-답변 형식 데이터로 "지시를 따르는" 법을 배웁니다.
  3. 선호도 학습(RLHF/DPO 등): 사람이 더 좋아하는 답을 내도록 조정합니다.
- **한계:** 학습 시점 이후 정보를 모르고(지식 컷오프), 그럴듯하지만 틀린 내용을 만들 수 있으며(환각), 한 번에 볼 수 있는 길이(컨텍스트 윈도우)가 제한됩니다.

아래 나오는 RAG, 에이전트, 파인튜닝, 양자화는 모두 이 한계를 보완하거나 LLM을 실제 서비스에 쓰기 위한 기법입니다.

</details>

<details>
<summary><b>Q2. RAG</b></summary>

**검색 증강 생성(Retrieval-Augmented Generation)** 은 LLM이 답하기 전에 외부 지식에서 관련 문서를 찾아 프롬프트에 넣어 주는 방식입니다.

- **해결하는 문제:** LLM이 모르는 최신 정보·사내 문서에 대해 답하게 하고, 근거 문서를 제시해 환각을 줄입니다.
- **기본 흐름:**
  1. 문서를 청크(조각)로 나누고 임베딩 벡터로 변환해 벡터 DB에 저장합니다(인덱싱).
  2. 질문이 들어오면 질문도 임베딩으로 바꿔 비슷한 청크를 검색합니다.
  3. 찾은 청크를 질문과 함께 프롬프트에 넣어 LLM이 답을 생성합니다.
- **장점:** 모델을 다시 학습하지 않고 지식을 갱신할 수 있고, 출처를 보여 줄 수 있습니다.
- **주의점:** 검색이 틀리면 답도 틀립니다. 청킹 방식, 임베딩 모델, 리랭킹 같은 검색 품질이 전체 품질을 좌우합니다.

</details>

<details>
<summary><b>Q3. MCP</b></summary>

**모델 컨텍스트 프로토콜(Model Context Protocol)** 은 LLM 애플리케이션이 외부 도구·데이터와 연결되는 방법을 표준화한 개방형 프로토콜입니다. Anthropic이 2024년에 공개했고, 지금은 여러 회사가 지원합니다.

- **해결하는 문제:** 앱마다 도구 연동 코드를 따로 짜야 하는 "N×M 통합" 문제입니다. MCP 서버를 한 번 만들면 MCP를 지원하는 어떤 클라이언트(Claude Desktop, IDE, 에이전트 등)에서도 쓸 수 있습니다.
- **구성:**
  - **호스트/클라이언트:** LLM을 실행하는 앱 쪽
  - **서버:** 도구(tools), 읽을 수 있는 데이터(resources), 프롬프트 템플릿(prompts)을 제공하는 쪽
  - 통신은 JSON-RPC 기반이며, 로컬(stdio)이나 원격(HTTP) 방식으로 연결합니다.
- **함수 호출과의 관계:** 함수 호출은 "모델이 도구를 부르는 방법"이고, MCP는 "도구를 어떻게 노출하고 발견하게 할지"에 대한 규약입니다. 둘은 경쟁 관계가 아니라 함께 쓰입니다.

</details>

<details>
<summary><b>Q4. 에이전트(Agent)</b></summary>

**AI 에이전트** 는 LLM이 목표를 달성할 때까지 스스로 계획하고, 도구를 호출하고, 결과를 보고 다음 행동을 정하는 반복 구조의 시스템입니다.

- **단순 LLM 호출과의 차이:** 단순 호출은 "입력 → 출력" 한 번으로 끝납니다. 에이전트는 "생각 → 행동(도구 호출) → 관찰"을 여러 번 반복합니다.
- **구성 요소:**
  - **모델:** 판단과 계획을 담당
  - **도구:** 검색, 코드 실행, API 호출, 파일 수정 등
  - **메모리:** 대화 기록, 중간 결과, 장기 기억
  - **루프와 종료 조건:** 언제 멈출지, 최대 몇 단계까지 갈지
- **예시:** "지난달 매출 보고서를 만들어 줘" → DB 조회 도구 호출 → 결과 분석 → 차트 생성 도구 호출 → 문서 작성 → 완료.
- **어려운 점:** 단계가 길어질수록 오류가 누적되고, 비용과 지연 시간이 커지며, 잘못된 도구 호출이 실제 피해(데이터 삭제 등)로 이어질 수 있습니다. 그래서 가드레일, 사람 승인 단계, 평가가 중요합니다.

</details>

<details>
<summary><b>Q5. 파인튜닝(Fine-tuning)</b></summary>

**파인튜닝** 은 이미 학습된 모델을 특정 작업이나 도메인 데이터로 추가 학습시켜 동작을 바꾸는 것입니다.

- **언제 쓰나:** 특정 출력 형식·말투를 일관되게 지키게 하거나, 특정 도메인 작업(분류, 추출 등)의 정확도를 높이거나, 큰 모델의 능력을 작은 모델에 옮기고 싶을 때 씁니다.
- **언제 쓰지 않나:** "새로운 지식을 넣고 싶다"가 목적이면 보통 RAG가 더 낫습니다. 파인튜닝은 지식 주입보다 **행동·형식·스타일** 을 바꾸는 데 강합니다.
- **방식:**
  - **전체 파인튜닝:** 모든 파라미터를 업데이트합니다. 성능은 좋지만 GPU 메모리와 비용이 많이 듭니다.
  - **PEFT(파라미터 효율적 파인튜닝):** LoRA처럼 작은 추가 파라미터만 학습합니다. 비용이 훨씬 적고 결과도 대부분 충분합니다.
- **위험:** 데이터 품질이 낮으면 성능이 오히려 떨어지고, 원래 가진 일반 능력을 잃는 파괴적 망각(catastrophic forgetting)이 생길 수 있습니다.

일반적인 선택 순서는 **프롬프트 엔지니어링 → RAG → 파인튜닝** 입니다. 앞 단계로 해결되지 않을 때 다음 단계를 검토합니다.

</details>

<details>
<summary><b>Q6. 양자화(Quantization)</b></summary>

**양자화** 는 모델 가중치(그리고 때로는 활성화 값)를 더 적은 비트로 표현해 메모리와 연산량을 줄이는 기법입니다.

- **예시:** FP16(16비트)로 저장된 7B 모델은 가중치만 약 14GB입니다. INT8로 바꾸면 약 7GB, INT4로 바꾸면 약 3.5GB가 됩니다.
- **효과:** 더 작은 GPU나 노트북·휴대폰에서도 모델을 돌릴 수 있고, 메모리 대역폭이 병목인 LLM 추론에서는 속도도 빨라지는 경우가 많습니다.
- **대가:** 비트를 줄일수록 정밀도가 떨어져 품질이 낮아질 수 있습니다. 8비트는 손실이 거의 없고, 4비트도 GPTQ·AWQ 같은 기법을 쓰면 실사용에 무리가 없는 경우가 많습니다. 2~3비트로 가면 품질 저하가 눈에 띄기 시작합니다.
- **종류:**
  - **학습 후 양자화(PTQ):** 학습이 끝난 모델을 변환합니다. 간단하고 흔히 씁니다.
  - **양자화 인식 학습(QAT):** 학습 중에 양자화 효과를 반영해 손실을 줄입니다.

</details>

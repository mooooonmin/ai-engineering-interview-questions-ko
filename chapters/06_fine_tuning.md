<summary><b>Q1. 파인튜닝이란 무엇이며, LLM은 언제 파인튜닝해야 하나요?</b></summary>

**파인튜닝** 은 사전 학습된 모델을 특정 작업·도메인·스타일의 데이터로 **추가 학습해 가중치를 조정** 하는 것입니다.

**파인튜닝이 잘 맞는 경우**

- **일관된 형식·어조:** 항상 특정 JSON 구조, 회사 고유의 말투, 정해진 보고서 양식
- **좁고 반복적인 작업:** 분류, 추출, 라우팅을 대량으로 처리 → 작은 모델을 파인튜닝해 큰 모델 수준의 정확도를 싸고 빠르게
- **긴 프롬프트 내재화:** 수천 토큰의 지시·예시를 매번 보내는 대신 모델에 학습시켜 비용·지연 절감
- **도메인 언어 적응:** 의료·법률·사내 용어의 쓰임새, 특정 프로그래밍 언어나 DSL
- **프롬프트로 안 되는 행동:** 여러 번 시도해도 프롬프트만으로 안정적으로 지켜지지 않는 동작
- **증류:** 큰 모델의 능력을 작은 모델로 옮기기

**파인튜닝이 맞지 않는 경우**

- **새로운·자주 바뀌는 지식 주입:** RAG가 더 정확하고 갱신이 쉽습니다. 파인튜닝으로 사실을 넣으면 환각이 오히려 늘 수 있습니다.
- **데이터가 거의 없음:** 품질 좋은 예시가 수백 개도 없으면 프롬프트·퓨샷이 낫습니다.
- **요구사항이 계속 바뀜:** 매번 재학습해야 합니다.

**결정 순서:** 프롬프트 엔지니어링 → RAG → 파인튜닝. 앞 단계로 평가 목표를 달성하지 못할 때 파인튜닝을 검토하고, 반드시 평가셋으로 효과를 비교합니다.

<summary><b>Q2. 전체 파인튜닝(full fine-tuning)과 파라미터 효율적 파인튜닝(PEFT)의 차이를 설명하세요.</b></summary>

| | 전체 파인튜닝 | PEFT (LoRA, QLoRA, 어댑터 등) |
|---|---|---|
| 학습하는 파라미터 | **모든** 가중치 | 전체의 0.1~1% 정도의 **추가·일부** 파라미터 |
| GPU 메모리 | 매우 큼 (가중치 + 기울기 + 옵티마이저 상태) | 작음 (원래 가중치는 고정) |
| 학습 속도·비용 | 높음 | 낮음 |
| 저장 | 작업마다 전체 모델 사본 (수십 GB) | 작업마다 작은 어댑터 (수 MB~수백 MB) |
| 성능 | 최고 상한, 큰 도메인 변화에 유리 | 대부분 작업에서 전체에 근접 |
| 망각 위험 | 큼 | 상대적으로 작음 |
| 서빙 | 작업별 모델 따로 | 기반 모델 하나 + 어댑터 교체(멀티 LoRA 서빙) |

**메모리가 왜 큰가 (전체 파인튜닝, Adam, 혼합 정밀도 기준)**

- 파라미터당 대략 가중치(2바이트) + 기울기(2) + FP32 마스터 가중치(4) + Adam 상태 2개(8) ≈ **16바이트**
- 7B 모델이면 약 112GB + 활성화 메모리 → 여러 장의 고급 GPU가 필요합니다.

**PEFT의 핵심 아이디어**

- 원래 가중치를 고정하고, 작은 추가 모듈만 학습합니다. 기울기와 옵티마이저 상태가 작은 모듈에만 필요해 메모리가 크게 줄어듭니다.
- 대표 방법: **LoRA**(저랭크 행렬), **QLoRA**(4비트 양자화 + LoRA), 어댑터 층, 프리픽스·프롬프트 튜닝.

**선택 기준:** 대부분의 실무 작업은 LoRA/QLoRA로 시작하고, 새 언어 학습처럼 모델을 크게 바꿔야 하거나 최고 성능이 필요하고 자원이 충분할 때 전체 파인튜닝을 고려합니다.

**더 읽어보기 (영문):** [AI Engineering Explained: LLM, RAG, MCP, Agent, Fine-Tuning, Quantization](https://www.youtube.com/watch?v=lnfWvX66FUk) (영상)

<summary><b>Q3. LoRA(Low-Rank Adaptation)란 무엇이며, 어떻게 동작하나요?</b></summary>

**LoRA** 는 가중치 행렬을 직접 바꾸지 않고, **변화량을 두 개의 작은 저랭크 행렬의 곱으로 학습** 하는 PEFT 기법입니다(Hu 외, 2021).

**핵심 가정:** 파인튜닝으로 생기는 가중치 변화 `ΔW`는 정보가 몇 개 방향에 집중된 **낮은 랭크** 구조를 가진다.

**동작**

- 원래 가중치 `W`(d×k)는 고정합니다.
- 변화량을 `ΔW = B·A`로 표현합니다. `A`는 r×k, `B`는 d×r, 랭크 r은 보통 8~64로 매우 작습니다.
- 순전파: `h = Wx + (α/r)·B·A·x`
- 초기화: `A`는 무작위, `B`는 0 → 학습 시작 시 `ΔW = 0`이라 원래 모델과 동일하게 출발합니다.

**파라미터 절약 예:** d = k = 4096, r = 16이면

- 전체: 4096 × 4096 ≈ 1,677만 개
- LoRA: 16 × (4096 + 4096) ≈ 13만 개 (약 0.8%)

**어디에 적용하나:** 주로 어텐션의 Q, K, V, O 투영 행렬. 최근에는 FFN 층까지 포함하면 성능이 더 좋다는 결과가 많습니다.

**장점**

- 메모리와 저장 공간이 작습니다.
- 학습 후 `W' = W + BA`로 **병합** 하면 추론 지연이 추가되지 않습니다.
- 병합하지 않으면 하나의 기반 모델에 여러 LoRA를 교체하며 서빙할 수 있습니다.

**주요 하이퍼파라미터:** 랭크 r, 스케일 α(보통 r의 1~2배), 적용 대상 모듈, 학습률(전체 파인튜닝보다 높게, 예: 1e-4~2e-4).

<summary><b>Q4. QLoRA란 무엇이며, 일반 소비자용 하드웨어에서 파인튜닝을 어떻게 가능하게 하나요?</b></summary>

**QLoRA** 는 기반 모델을 **4비트로 양자화해 메모리에 올리고**, 그 위에 **LoRA 어댑터를 16비트로 학습** 하는 방법입니다(Dettmers 외, 2023). 큰 모델을 단일 GPU에서 파인튜닝할 수 있게 만들었습니다.

**핵심 기술**

1. **4비트 NormalFloat(NF4)**
   - 신경망 가중치가 대략 정규분포를 따른다는 점에 맞춰 설계한 4비트 데이터 타입으로, 일반 4비트 정수보다 정보 손실이 적습니다.
2. **이중 양자화(Double Quantization)**
   - 양자화에 필요한 스케일 값(상수)까지 다시 양자화해 메모리를 더 줄입니다.
3. **페이지드 옵티마이저(Paged Optimizers)**
   - GPU 메모리가 순간적으로 부족해지면 옵티마이저 상태를 CPU 메모리로 넘겨 메모리 부족 오류를 피합니다.

**동작**

- 순전파·역전파 때 4비트 가중치를 필요한 순간에만 16비트로 복원(dequantize)해 계산합니다.
- 기울기는 LoRA 파라미터에 대해서만 계산·저장합니다. 기반 모델 가중치는 고정입니다.

**효과 (대략적인 규모)**

- 원 논문은 65B 모델을 48GB GPU 한 장에서 파인튜닝했습니다.
- 7B~8B 모델은 16~24GB 소비자용 GPU에서도 파인튜닝이 가능해졌습니다.
- 품질은 16비트 LoRA와 비슷한 수준으로 보고되었습니다.

**트레이드오프**

- 양자화·복원 과정 때문에 학습 속도는 일반 LoRA보다 느립니다.
- 배포 시에는 어댑터를 16비트 기반 모델에 병합하거나, 양자화된 모델 + 어댑터로 서빙합니다(병합 시 정밀도 차이에 주의).

**도구:** Hugging Face PEFT + bitsandbytes, Unsloth, Axolotl 등.

**더 읽어보기 (영문):** [AI Engineering Explained: LLM, RAG, MCP, Agent, Fine-Tuning, Quantization](https://www.youtube.com/watch?v=lnfWvX66FUk) (영상)

<summary><b>Q5. 파인튜닝은 어떻게 동작하나요?</b></summary>

**전체 흐름**

1. **기반 모델 선택:** 작업에 맞는 크기와 라이선스의 사전 학습 모델(보통 지시 튜닝된 instruct 모델)을 고릅니다.
2. **데이터 준비:** 입력-출력 쌍을 모델의 **채팅 템플릿 형식** 으로 만듭니다.
   ```json
   {"messages": [{"role": "system", "content": "..."},
                 {"role": "user", "content": "이 리뷰를 분류해 줘: ..."},
                 {"role": "assistant", "content": "{\"label\": \"negative\"}"}]}
   ```
3. **학습 설정:** 전체 또는 LoRA/QLoRA, 학습률, 에포크, 배치 크기, 최대 길이.
4. **학습:**
   - 데이터를 토큰화해 모델에 넣고, **정답(어시스턴트 응답) 토큰에 대해서만** 다음 토큰 예측 손실(교차 엔트로피)을 계산합니다. 프롬프트 부분은 손실에서 제외(마스킹)하는 것이 일반적입니다.
   - 역전파로 기울기를 구하고 옵티마이저(AdamW)로 가중치(또는 어댑터)를 갱신합니다.
5. **검증:** 학습 중 검증 손실을 보고 과적합을 감시합니다.
6. **평가:** 별도 테스트셋에서 작업 지표와 일반 능력(망각 여부)을 확인합니다.
7. **배포:** 어댑터 병합 또는 어댑터 서빙, 양자화 후 배포.

**본질:** 사전 학습과 같은 "다음 토큰 예측" 학습을, 원하는 행동을 보여 주는 작은 데이터셋으로 **짧고 낮은 학습률로** 이어서 하는 것입니다. 모델이 이미 가진 능력을 원하는 방향으로 "조정"합니다.

**관리형 서비스:** OpenAI·Google·AWS 등의 파인튜닝 API는 데이터만 올리면 학습과 배포를 처리해 줍니다. 오픈 모델은 Hugging Face TRL, Axolotl, Unsloth 등으로 직접 학습합니다.

<summary><b>Q6. 프리픽스 튜닝(Prefix Tuning)과 프롬프트 튜닝(Prompt Tuning)을 설명하세요. LoRA와는 어떻게 다른가요?</b></summary>

**프롬프트 튜닝 (Lester 외, 2021)**

- 입력 임베딩 앞에 학습 가능한 **가상 토큰 벡터** 몇 개(예: 20개)를 붙입니다.
- 모델 가중치는 모두 고정하고 이 벡터만 학습합니다.
- 입력층에만 영향을 주므로 파라미터가 극히 적습니다. 큰 모델일수록 효과가 좋습니다.

**프리픽스 튜닝 (Li & Liang, 2021)**

- 입력층뿐 아니라 **모든 트랜스포머 층의 어텐션** 에 학습 가능한 프리픽스 벡터(K, V)를 추가합니다.
- 각 층에서 토큰들이 이 프리픽스에 어텐션할 수 있어 프롬프트 튜닝보다 표현력이 큽니다.
- 학습 안정화를 위해 작은 MLP로 프리픽스를 생성하는 재매개변수화를 쓰기도 합니다.

**LoRA와 비교**

| | 프롬프트 튜닝 | 프리픽스 튜닝 | LoRA |
|---|---|---|---|
| 수정 위치 | 입력 임베딩 | 모든 층의 어텐션 K, V | 가중치 행렬 (저랭크 변화량) |
| 학습 파라미터 | 가장 적음 | 적음 | 적음 |
| 성능 | 작은 모델에서 약함 | 중간 | 대체로 가장 좋음 |
| 추론 비용 | 시퀀스가 길어짐 | 어텐션 대상이 늘어남 | 병합하면 추가 비용 없음 |
| 컨텍스트 사용 | 가상 토큰만큼 차지 | 프리픽스만큼 차지 | 없음 |

**왜 LoRA가 주류가 되었나:** 성능이 전체 파인튜닝에 가깝고, 학습이 안정적이며, 병합하면 추론 비용이 0입니다. 프롬프트·프리픽스 튜닝은 극히 적은 저장 공간이 중요하거나 하나의 모델로 매우 많은 작업을 동시에 서빙할 때 고려합니다.

**더 읽어보기 (영문):** [How does Prefix Tuning work?](https://outcomeschool.com/blog/how-does-prefix-tuning-work)

<summary><b>Q7. 어댑터(adapter) 기반 파인튜닝이란 무엇인가요?</b></summary>

**어댑터** 는 사전 학습된 모델의 각 층 사이에 **작은 신경망 모듈을 끼워 넣고, 이 모듈만 학습** 하는 방식입니다(Houlsby 외, 2019). PEFT의 초기 대표 방법입니다.

**구조 (병목 어댑터)**

```
입력 h (d차원)
 → 다운 투영 (d → m, 예: 4096 → 64)
 → 비선형 활성화
 → 업 투영 (m → d)
 → 잔차 더하기: h + adapter(h)
```

- 트랜스포머 블록의 어텐션 뒤, FFN 뒤에 삽입합니다.
- 업 투영을 0에 가깝게 초기화해 학습 시작 시 원래 모델과 같게 동작합니다.

**장점**

- 원래 가중치를 고정하므로 작업별로 작은 어댑터만 저장하면 됩니다.
- 여러 작업 어댑터를 교체하거나, 언어 어댑터 + 작업 어댑터처럼 **조합(AdapterFusion, MAD-X)** 할 수 있습니다.
- 파괴적 망각이 적습니다.

**단점**

- 층이 추가되어 **추론 지연이 늘어납니다**(직렬로 계산해야 함). LoRA처럼 원래 가중치에 병합할 수 없습니다.

**넓은 의미의 "어댑터"**

- 요즘은 LoRA 모듈도 흔히 "LoRA 어댑터"라고 부릅니다. 즉 "기반 모델은 그대로 두고 작은 추가 파라미터로 작업에 적응시키는 것"을 통틀어 어댑터 방식이라고 합니다.
- 실무에서는 병합 가능하고 성능이 좋은 LoRA 계열이 가장 많이 쓰입니다.

<details>
<summary><b>Q8. 사전 학습(pre-training), 지도 파인튜닝(SFT), 선호도 최적화(RLHF/DPO)의 차이를 설명하세요.</b></summary>

현대 LLM은 보통 이 세 단계를 거쳐 만들어집니다.

| | 사전 학습 | 지도 파인튜닝 (SFT) | 선호도 최적화 (RLHF/DPO) |
|---|---|---|---|
| 목적 | 언어·지식·추론의 기반 능력 | 지시를 따르는 대화형 비서로 | 사람이 더 선호하는 답을 내도록 |
| 데이터 | 수조 토큰의 웹·책·코드 (라벨 없음) | 수만~수십만 개 (지시, 모범 답변) 쌍 | (프롬프트, 더 좋은 답, 더 나쁜 답) 비교 데이터 |
| 학습 목표 | 다음 토큰 예측 | 모범 답변의 다음 토큰 예측 | 보상 최대화(RL) 또는 선호 쌍 직접 학습(DPO) |
| 비용 | 매우 큼 (수천 GPU, 수개월) | 작음~중간 | 중간 |
| 결과 | 베이스 모델: 글을 이어 쓰지만 지시는 잘 안 따름 | 지시를 따르고 형식을 지킴 | 더 유용하고 안전하며 사람 취향에 맞음 |

**비유**

- 사전 학습: 엄청난 양의 책을 읽어 세상 지식을 쌓은 상태
- SFT: 모범 답안을 보며 "질문에 이렇게 답하는 것"을 배움
- 선호도 최적화: 두 답안 중 무엇이 더 나은지 피드백을 받으며 다듬음

**왜 SFT만으로는 부족한가**

- SFT는 모범 답안을 "따라 하기"만 합니다. 무엇이 나쁜 답인지는 배우지 않습니다.
- 사람은 좋은 답을 직접 쓰기보다 두 답을 비교하는 것이 훨씬 쉽고 일관됩니다. 선호도 학습은 이 비교 신호를 활용해 미묘한 품질(정확성, 어조, 안전성)을 개선합니다.

**최근 흐름:** 수학·코드처럼 정답 확인이 가능한 영역에서는 **검증 가능한 보상을 쓰는 강화학습(RLVR)** 이 추가 단계로 중요해졌습니다(추론 모델).

**더 읽어보기 (영문):** [Decoding InstructGPT](https://outcomeschool.com/blog/decoding-instructgpt)

<summary><b>Q9. RLHF(Reinforcement Learning from Human Feedback)란 무엇이며, LLM을 정렬(alignment)하는 데 어떻게 사용되나요?</b></summary>

**RLHF** 는 사람의 선호 판단을 학습 신호로 삼아, 강화학습으로 LLM이 **사람이 더 좋다고 평가하는 응답** 을 생성하도록 조정하는 방법입니다. InstructGPT(2022)와 ChatGPT로 널리 알려졌습니다.

**3단계 과정**

1. **SFT (지도 파인튜닝)**
   - 사람이 작성한 모범 답변으로 기반 모델을 파인튜닝합니다.
2. **보상 모델 학습**
   - 같은 프롬프트에 대해 모델이 여러 답을 생성하고, 사람이 순위를 매깁니다.
   - 이 비교 데이터로 "응답 → 점수"를 예측하는 보상 모델을 학습합니다(더 선호된 답의 점수가 높아지도록, Bradley-Terry 손실).
3. **강화학습 (주로 PPO)**
   - 정책(LLM)이 응답을 생성하면 보상 모델이 점수를 매기고, 그 점수를 최대화하도록 정책을 업데이트합니다.
   - **KL 페널티:** 정책이 SFT 모델에서 너무 멀어지지 않게 제약해, 보상 모델의 허점을 파고드는 이상한 출력(보상 해킹)을 막습니다.

$$\max_\pi \ \mathbb{E}[r(x, y)] - \beta \cdot KL(\pi \parallel \pi_{SFT})$$

**정렬에 주는 효과**

- 유용성(Helpful): 질문 의도에 맞는 답
- 정직성(Honest): 모를 때 인정, 사실성 향상
- 무해성(Harmless): 유해 요청 거절

**한계**

- 사람 라벨링 비용이 크고, 라벨러 간 의견 불일치가 있습니다.
- 보상 해킹, 아첨(sycophancy), 길이 편향.
- PPO는 모델 4개(정책, 참조, 보상, 가치)가 필요해 무겁고 불안정합니다. 그래서 DPO, GRPO, RLAIF 같은 대안이 나왔습니다.

**더 읽어보기 (영문):** [Reinforcement Learning from Human Feedback (RLHF)](https://outcomeschool.com/blog/reinforcement-learning-from-human-feedback-rlhf)

<summary><b>Q10. RLHF의 시작이 된 논문인 "Deep RL from Human Preferences"란 무엇인가요?</b></summary>

**"Deep Reinforcement Learning from Human Preferences"** (Christiano 외, 2017)는 OpenAI와 DeepMind 연구자들이 발표한 논문으로, **보상 함수를 직접 설계하기 어려운 작업에서, 사람의 비교 판단만으로 보상을 학습해 강화학습을 하는 방법** 을 제시했습니다. 이후 LLM의 RLHF로 이어진 핵심 아이디어의 출발점입니다.

**문제 의식**

- 강화학습은 보상 함수가 필요한데, "로봇이 자연스럽게 뒤로 공중제비를 돈다" 같은 목표는 수식으로 정의하기 어렵습니다.
- 사람이 매 순간 점수를 매기는 것은 비용이 너무 큽니다.

**방법**

1. 에이전트가 행동한 **짧은 영상 클립 두 개** 를 사람에게 보여 주고 "어느 쪽이 목표에 더 가까운가"만 고르게 합니다.
2. 이 비교 데이터로 **보상 모델** 을 학습합니다(선호된 쪽의 보상 합이 더 크도록).
3. 에이전트는 학습된 보상 모델을 보상으로 삼아 강화학습을 합니다.
4. 에이전트가 새로운 행동을 하면 다시 비교를 받아 보상 모델을 갱신합니다(반복).

**결과**

- 아타리 게임과 로봇 시뮬레이션에서, 실제 보상의 극히 일부에 해당하는 사람 피드백(수백~수천 번 비교)만으로 의미 있는 학습이 가능했습니다.
- 수식으로 정의하기 어려운 행동(공중제비)도 학습했습니다.

**LLM으로의 연결**

- 같은 구조(비교 데이터 → 보상 모델 → RL)가 요약 모델 학습(2020), InstructGPT(2022)를 거쳐 ChatGPT의 RLHF가 되었습니다.
- "사람은 절대 점수보다 **상대 비교** 를 더 잘하고 일관되게 한다"는 통찰이 지금의 선호도 학습 전반의 기반입니다.

**더 읽어보기 (영문):** [Deep RL from Human Preferences](https://outcomeschool.com/blog/decoding-deep-rl-from-human-preferences)

<summary><b>Q11. 왜 많은 연구소에서 DPO가 PPO 기반 RLHF를 대체했나요? 온라인 RL이 여전히 더 나은 경우는 언제인가요?</b></summary>

**DPO가 확산된 이유**

1. **단순성:** 보상 모델과 가치 모델을 따로 학습할 필요가 없고, 선호 쌍 데이터로 지도 학습처럼 바로 학습합니다.
2. **자원 효율:** PPO는 정책·참조·보상·가치 모델 4개를 메모리에 올려야 하지만, DPO는 정책과 참조 모델 2개면 됩니다.
3. **안정성:** RL 특유의 불안정성(하이퍼파라미터 민감, 발산)이 적습니다.
4. **재현성:** 오프라인 데이터로 학습하므로 실험을 재현하기 쉽습니다.
5. **충분한 성능:** 대화 품질·어조 같은 선호 정렬에서는 PPO와 비슷한 결과를 보여 오픈소스 모델 정렬의 표준이 되었습니다.

**온라인 RL(PPO, GRPO 등)이 여전히 더 나은 경우**

1. **검증 가능한 보상이 있는 작업:** 수학 정답, 코드 테스트 통과처럼 자동으로 채점할 수 있으면, 모델이 직접 생성한 답을 바로 채점해 학습하는 온라인 RL이 훨씬 강력합니다. 추론 모델(R1 등)이 이 방식으로 만들어졌습니다.
2. **탐색이 필요한 경우:** DPO는 고정된 데이터에 있는 응답만 학습합니다. 온라인 RL은 모델이 새로운 풀이 방법을 시도하고, 그중 잘된 것을 강화할 수 있습니다.
3. **분포 차이 문제:** 학습할수록 모델 출력이 기존 데이터와 달라지는데, DPO는 이를 반영하지 못합니다. 온라인 방식은 항상 현재 모델의 출력으로 학습합니다.
4. **긴 다단계 작업:** 에이전트·도구 사용처럼 여러 단계의 결과로 보상이 정해지는 작업.

**절충안:** 온라인/반복 DPO(현재 모델로 새 응답 생성 → 선호 라벨링 → DPO 반복)로 두 방식의 장점을 섞기도 합니다.

**더 읽어보기 (영문):** [Direct Preference Optimization (DPO)](https://outcomeschool.com/blog/direct-preference-optimization-dpo), [Proximal Policy Optimization (PPO)](https://outcomeschool.com/blog/proximal-policy-optimization-ppo)

<summary><b>Q12. 인스트럭션 튜닝(instruction tuning)이란 무엇이며, 채팅 모델에 왜 중요한가요?</b></summary>

**인스트럭션 튜닝** 은 다양한 작업을 **"지시문 → 응답"** 형태로 만든 데이터로 모델을 파인튜닝해, 모델이 **사람의 지시를 이해하고 따르도록** 만드는 학습입니다. 지도 파인튜닝(SFT)의 대표적인 형태입니다.

**왜 필요한가: 베이스 모델의 한계**

- 사전 학습만 한 모델은 "글 이어 쓰기"를 합니다.
- "프랑스의 수도는?"이라고 입력하면 답 대신 "독일의 수도는? 이탈리아의 수도는?"처럼 비슷한 문장을 이어 쓸 수 있습니다.
- 인스트럭션 튜닝 후에는 "파리입니다"라고 답합니다.

**데이터 예**

```
지시: 다음 문장을 존댓말로 바꿔 줘.
입력: 내일 회의 몇 시야?
응답: 내일 회의는 몇 시인가요?
```

- 요약, 번역, 분류, 질의응답, 코딩, 추론 등 **수천 가지 작업 유형** 을 섞을수록 처음 보는 지시에도 일반화가 잘 됩니다(FLAN 연구).

**채팅 모델에 중요한 이유**

- 지시를 따르는 능력, 대화 형식(채팅 템플릿과 역할 구분), 응답의 끝을 아는 능력(정지 토큰)을 학습합니다.
- 이후 RLHF/DPO 같은 선호도 학습의 출발점이 됩니다.

**데이터 품질이 핵심**

- 소량이라도 고품질·다양한 데이터가 대량의 저품질 데이터보다 낫다는 결과(LIMA 등)가 있습니다.
- 최근에는 강한 모델로 합성한 지시 데이터도 많이 씁니다.

**더 읽어보기 (영문):** [Decoding InstructGPT](https://outcomeschool.com/blog/decoding-instructgpt)

<summary><b>Q13. LLM 파인튜닝용 데이터셋은 어떻게 준비하나요?</b></summary>

**1. 목표와 형식 정의**

- 모델이 할 작업, 입력 형태, 원하는 출력 형식·어조를 명확히 합니다.
- 평가 방법을 먼저 정합니다(무엇이 "좋은 출력"인지).

**2. 데이터 수집**

- **실제 데이터:** 운영 로그, 상담 기록, 사람이 작성한 결과물 (가장 가치 있음)
- **사람 작성:** 전문가가 모범 답안 작성
- **합성 데이터:** 강한 LLM으로 생성 → 반드시 검수·필터링
- 실제 사용 분포를 대표하고, 쉬운·어려운·엣지 케이스를 고르게 포함합니다.

**3. 정제와 품질 관리**

- 중복 제거(정확·근사 중복), 오류·모순된 라벨 수정
- 개인정보·민감 정보 제거 또는 가명 처리
- 형식 일관성 확인 (같은 작업이면 같은 출력 구조)
- 무작위 샘플을 사람이 직접 검토합니다. **데이터 품질이 결과를 결정합니다.**

**4. 형식 변환**

- 사용할 모델의 **채팅 템플릿** 에 맞게 `system/user/assistant` 메시지로 구성합니다.
- 학습 시 추론 때와 같은 시스템 프롬프트·형식을 쓰는 것이 중요합니다.

**5. 분할**

- 학습/검증/테스트로 나누고, 같은 출처의 거의 같은 예시가 학습과 테스트에 동시에 들어가지 않게 합니다(데이터 누수 방지).

**6. 양 기준 (대략)**

- 형식·스타일 학습: 수백~수천 개
- 특정 작업 성능 향상: 수천~수만 개
- 적은 양으로 먼저 학습해 보고, 데이터를 늘릴 때 성능이 오르는지 확인합니다.

**7. 균형과 혼합**

- 클래스 불균형 조정, 일반 대화 데이터 일부를 섞어 망각 방지.

<summary><b>Q14. 파괴적 망각(catastrophic forgetting)이란 무엇이며, 파인튜닝 중에 어떻게 방지하나요?</b></summary>

**파괴적 망각** 은 새 작업으로 모델을 학습할 때, **이전에 잘하던 능력이 크게 떨어지는 현상** 입니다. 예: 의료 문서 요약으로 파인튜닝했더니 일반 대화, 수학, 코딩 능력이 나빠짐.

**왜 생기나:** 새 데이터의 손실을 줄이는 방향으로 가중치가 바뀌면서, 기존 능력에 중요했던 가중치까지 함께 바뀌기 때문입니다. 데이터가 좁을수록, 학습률이 높을수록, 오래 학습할수록 심합니다.

**방지 방법**

1. **PEFT 사용 (LoRA 등):** 원래 가중치를 고정하고 작은 어댑터만 학습해 망각이 크게 줄어듭니다. 낮은 랭크 자체가 일종의 정규화 역할을 합니다.
2. **데이터 혼합(리플레이):** 새 작업 데이터에 일반 지시 데이터·이전 작업 데이터를 일정 비율 섞습니다.
3. **학습 강도 조절:** 낮은 학습률, 적은 에포크, 조기 종료(검증 손실·일반 벤치마크 모니터링).
4. **정규화:** 원래 가중치에서 크게 벗어나지 않도록 페널티(EWC, L2-SP)나 원래 모델 출력과의 KL 제약.
5. **모델 병합:** 파인튜닝 모델과 원래 모델의 가중치를 보간하거나 병합해 균형점을 찾습니다.
6. **작업별 어댑터 분리:** 하나의 모델에 모든 것을 학습시키지 않고 작업별 LoRA를 따로 두어 필요할 때 교체합니다.

**측정:** 파인튜닝 전후로 **목표 작업 성능** 과 **일반 능력 벤치마크**(지시 따르기, 추론, 지식)를 함께 비교합니다. 목표 성능만 보면 망각을 놓칩니다.

<summary><b>Q15. 파인튜닝, RAG, 프롬프트 엔지니어링 중 각각은 언제 선택해야 하나요?</b></summary>

**한 줄 요약**

- **프롬프트 엔지니어링:** 모델이 이미 할 수 있는 일을 잘하게 만들 때
- **RAG:** 모델이 모르는 **지식** 을 제공해야 할 때
- **파인튜닝:** 모델의 **행동·형식·스타일** 을 바꾸거나, 비용·지연을 줄여야 할 때

| 상황 | 추천 |
|---|---|
| 빠른 프로토타입, 요구사항이 자주 바뀜 | 프롬프트 |
| 사내 문서, 최신 정보, 출처 제시 필요 | RAG |
| 사용자별 접근 권한이 다른 데이터 | RAG |
| 매우 일관된 출력 형식·말투가 필요 | 파인튜닝 (또는 구조화 출력) |
| 대량의 분류·추출을 싸고 빠르게 | 작은 모델 파인튜닝 |
| 프롬프트가 너무 길어 비용이 큼 | 파인튜닝으로 내재화 |
| 도메인 특유의 추론 방식·전문 언어 | 파인튜닝 (+ RAG) |

**비교 기준**

| | 프롬프트 | RAG | 파인튜닝 |
|---|---|---|---|
| 구축 속도 | 즉시 | 수일~수주 | 수주 (데이터 준비 포함) |
| 초기 비용 | 거의 없음 | 인프라 구축 | 데이터·학습 |
| 지식 갱신 | 프롬프트 수정 | 문서 갱신 | 재학습 |
| 필요한 데이터 | 예시 몇 개 | 문서 | 라벨된 예시 수백~수천 |

**실무 순서:** 프롬프트로 시작해 평가셋으로 기준선을 잡고 → 지식이 부족하면 RAG → 그래도 행동·형식·비용 목표를 못 맞추면 파인튜닝. 실제 시스템은 **세 가지를 함께** 쓰는 경우가 많습니다.

<summary><b>Q17. 합성 데이터 생성(synthetic data generation)이란 무엇이며, 파인튜닝에 어떻게 활용하나요?</b></summary>

**합성 데이터** 는 사람이 직접 만들거나 수집한 데이터가 아니라, **LLM 같은 모델이나 규칙으로 생성한 학습 데이터** 입니다.

**왜 쓰나**

- 라벨 데이터가 부족하거나 만들기 비쌀 때(전문가 라벨링 비용)
- 개인정보 때문에 실제 데이터를 쓸 수 없을 때
- 드문 사례(엣지 케이스, 공격 사례)를 늘리고 싶을 때
- 다양성을 체계적으로 확보하고 싶을 때

**생성 방법**

1. **질문·지시 생성:** 강한 모델에게 다양한 주제·난이도·스타일의 질문을 만들게 합니다. 페르소나, 주제 목록을 시드로 주면 다양성이 높아집니다(Self-Instruct, Evol-Instruct).
2. **문서 기반 생성:** 사내 문서를 주고 "이 문서로 답할 수 있는 질문과 답"을 생성 → RAG·임베딩 학습용 데이터.
3. **응답 생성(증류):** 강한 모델이 모범 답변·추론 과정을 작성.
4. **변형·증강:** 기존 예시를 바꿔 쓰기, 노이즈·오타 추가, 다른 언어로 번역.
5. **검증 가능한 생성:** 수학·코드처럼 정답을 확인할 수 있는 문제를 생성하고, 맞는 답만 남김.

**품질 관리 (가장 중요)**

- 중복 제거, 다양성 측정(임베딩 클러스터링)
- LLM 판정자·규칙으로 오류·저품질 필터링
- 사람이 샘플을 검수
- 평가셋과 겹치지 않게 관리(오염 방지)

**위험**

- **모델 붕괴:** 모델이 만든 데이터만으로 반복 학습하면 다양성이 줄고 품질이 저하될 수 있습니다. 실제 데이터와 섞습니다.
- 생성 모델의 편향·오류가 그대로 전이됩니다.
- 상용 모델 출력의 학습 사용은 이용 약관을 확인해야 합니다.

<summary><b>Q19. 7B 모델을 bf16과 Adam으로 전체 파인튜닝할 때 필요한 GPU 메모리를 계산해 보세요. LoRA와 QLoRA를 쓰는 경우도 계산해 보세요.</b></summary>

파라미터 수 N = 7×10⁹ 기준, **활성화 메모리는 별도**(배치·시퀀스 길이에 따라 수 GB~수십 GB, 그래디언트 체크포인팅으로 줄일 수 있음)로 두고 계산합니다.

**1. 전체 파인튜닝 (bf16 혼합 정밀도 + Adam)**

| 항목 | 파라미터당 바이트 | 7B 기준 |
|---|---|---|
| bf16 가중치 | 2 | 14 GB |
| bf16 기울기 | 2 | 14 GB |
| fp32 마스터 가중치 | 4 | 28 GB |
| Adam 1차 모멘트 (fp32) | 4 | 28 GB |
| Adam 2차 모멘트 (fp32) | 4 | 28 GB |
| **합계** | **16** | **약 112 GB** |

- 여기에 활성화 메모리가 더해져 80GB GPU 한 장으로는 부족하고, 여러 장에 ZeRO/FSDP로 나눠야 합니다.
- (옵티마이저 상태까지 bf16으로 두는 등 정밀도를 낮추면 파라미터당 8바이트 수준인 약 56GB까지 줄일 수 있지만 안정성 트레이드오프가 있습니다.)

**2. LoRA (기반 모델 bf16 고정)**

- 고정된 bf16 가중치: 7B × 2 = **약 14 GB**
- LoRA 파라미터: 설정에 따라 대략 2천만~8천만 개(전체의 0.3~1%). 이 부분만 16바이트/파라미터 → **약 0.3~1.3 GB**
- 기울기·옵티마이저 상태는 LoRA 파라미터에만 필요
- **합계: 약 15~16 GB + 활성화** → 24GB GPU 한 장에서 가능한 수준

**3. QLoRA (기반 모델 4비트)**

- 4비트 가중치: 7B × 0.5 = 3.5 GB + 양자화 상수 등 → **약 4 GB**
- LoRA 파라미터·옵티마이저: **약 0.3~1 GB**
- **합계: 약 5~6 GB + 활성화** → 12~16GB 소비자용 GPU에서도 가능

**요약**

| 방식 | 대략적인 메모리 (활성화 제외) |
|---|---|
| 전체 파인튜닝 | ~112 GB |
| LoRA | ~15 GB |
| QLoRA | ~5 GB |

**면접 팁:** "파라미터당 16바이트"라는 혼합 정밀도 Adam 공식을 기억하고, 활성화 메모리가 별도라는 점과 줄이는 방법(그래디언트 체크포인팅, 짧은 시퀀스, 작은 마이크로 배치)을 함께 말하면 좋습니다.

<summary><b>Q20. 특정 도메인(법률, 의료, 금융)에 맞게 모델을 어떻게 파인튜닝하나요?</b></summary>

**1. 정말 파인튜닝이 필요한지 먼저 확인**

- 도메인 **지식** 이 부족한 것이 문제라면 RAG가 우선입니다(최신 법령, 내부 규정, 의학 가이드라인).
- 도메인의 **언어 사용, 추론 방식, 출력 형식** 이 문제라면 파인튜닝이 효과적입니다.

**2. 단계별 접근**

1. **(선택) 지속 사전 학습:** 도메인 텍스트(판례, 의학 논문, 재무 보고서)가 대량 있고 모델이 용어 자체를 잘 모르면, 라벨 없는 도메인 텍스트로 추가 사전 학습을 합니다. 일반 데이터를 섞어 망각을 막습니다.
2. **지도 파인튜닝:** 실제 업무 형태의 (질문, 전문가 답변) 데이터로 SFT. 예: 계약 조항 → 위험 분석, 진료 기록 → 요약, 공시 → 핵심 지표 추출.
3. **(선택) 선호도 학습:** 전문가가 두 답변 중 더 나은 것을 고른 데이터로 DPO.

**3. 데이터**

- **전문가 참여가 필수** 입니다. 라벨 기준(가이드라인)을 문서화하고, 전문가 간 일치도를 측정합니다.
- 실제 업무 분포를 반영하고, 어려운 사례·애매한 사례를 포함합니다.
- 개인정보(환자, 고객)는 비식별화하고 규제(HIPAA, 개인정보보호법, 금융 규제)를 준수합니다.

**4. 평가**

- 도메인 전문가가 만든 평가셋, 전문가 블라인드 평가.
- 사실 오류의 **심각도** 를 구분해 측정합니다(치명적 오류율).
- 일반 능력·안전성 유지 확인.

**5. 배포 시 안전 장치**

- 고위험 도메인이므로 RAG로 근거 제시, 불확실할 때 거절, 전문가 최종 검토(사람 승인), 면책 고지.
- 규정 변경 시 재평가·재학습 계획.

</details>

<summary><b>Q21. 지속 사전 학습(continual pre-training)이란 무엇이며, 언제 사용하나요?</b></summary>

**지속 사전 학습(CPT)** 은 이미 사전 학습된 모델을 **라벨 없는 새로운 대량 텍스트로 다음 토큰 예측 학습을 이어서** 하는 것입니다. SFT가 "지시 따르기"를 가르친다면, CPT는 **새로운 언어·도메인의 분포 자체** 를 익히게 합니다.

**언제 쓰나**

- **새 언어 추가:** 영어 중심 모델의 한국어 능력을 크게 높이고 싶을 때 (대량 한국어 코퍼스 필요)
- **전문 도메인 적응:** 의학·법률·금융·특정 프로그래밍 언어 텍스트가 수십억 토큰 이상 있고, 기존 모델이 용어와 문체를 잘 모를 때
- **지식 업데이트:** 특정 시점 이후의 대량 텍스트를 반영할 때 (단, 자주 바뀌는 지식은 RAG가 더 적합)
- **긴 컨텍스트 확장:** 긴 문서로 추가 학습해 컨텍스트 길이를 늘릴 때

**SFT와 비교**

| | 지속 사전 학습 | SFT |
|---|---|---|
| 데이터 | 라벨 없는 원문 텍스트, 수억~수천억 토큰 | (지시, 응답) 쌍, 수천~수십만 개 |
| 목적 | 분포·지식·언어 습득 | 행동·형식 |
| 비용 | 큼 | 작음 |
| 후속 작업 | 보통 이후 SFT·정렬이 다시 필요 | 바로 사용 가능 |

**주의점**

- **파괴적 망각:** 일반 사전 학습 데이터를 일정 비율 섞습니다(리플레이).
- **학습률 재워밍업:** 끝난 학습률 스케줄을 다시 올렸다 내리는 설정이 중요합니다.
- 지시 튜닝된 모델에 CPT를 하면 지시 따르기 능력이 약해지므로, 베이스 모델에 CPT → SFT 순서가 일반적입니다.
- 비용 대비 효과를 따져, 데이터가 충분히 크지 않으면 SFT + RAG로 해결하는 편이 낫습니다.

</details>

<summary><b>Q22. 여러 LoRA 어댑터를 어떻게 병합하나요?</b></summary>

**두 가지 의미의 "병합"**

1. **어댑터를 기반 모델에 병합:** `W' = W + (α/r)·B·A`로 가중치에 더해 일반 모델처럼 배포합니다. 추론 지연이 없어집니다.
2. **여러 어댑터를 합치기:** 서로 다른 작업(예: SQL 생성 + 한국어 문체)으로 학습한 LoRA들을 하나로 합쳐 두 능력을 함께 갖게 합니다.

**여러 어댑터를 합치는 방법**

- **선형 결합:** 각 어댑터의 변화량 `ΔW_i = B_i A_i`를 가중합합니다.
  ```
  ΔW = w₁·B₁A₁ + w₂·B₂A₂
  ```
  (주의: A와 B를 각각 따로 평균 내면 곱의 결과가 달라지므로, 변화량 ΔW 기준으로 합치거나 이를 지원하는 방식을 씁니다.)
- **어댑터 이어 붙이기(concat):** 두 어댑터를 랭크 방향으로 이어 붙여 랭크 r₁+r₂인 하나의 어댑터로 만듭니다. 정보 손실이 없습니다.
- **TIES-Merging:** 작은 변화는 버리고(trim), 파라미터별 부호 충돌을 다수결로 정리한 뒤(elect sign) 합칩니다. 어댑터 간 간섭을 줄입니다.
- **DARE:** 변화량의 일부를 무작위로 버리고 나머지를 키운 뒤 합칩니다(TIES와 함께 쓰기도 함).
- **SVD 재압축:** 합친 ΔW를 SVD로 다시 저랭크 어댑터로 압축합니다.

**도구:** Hugging Face PEFT의 `add_weighted_adapter`, mergekit.

**병합 대신 쓰는 대안**

- **멀티 LoRA 서빙:** 하나의 기반 모델에 여러 어댑터를 올려 두고 요청마다 필요한 어댑터를 적용합니다(vLLM, LoRAX). 병합으로 인한 간섭이 없습니다.
- **라우팅:** 요청 유형에 따라 다른 어댑터 선택.

**검증:** 병합 후 각 작업의 성능을 개별 어댑터와 비교해, 간섭으로 인한 성능 저하를 확인합니다.

**더 읽어보기 (영문):** [LoRA - Low-Rank Adaptation of LLMs](https://outcomeschool.com/blog/lora-low-rank-adaptation-of-llms)

<summary><b>Q23. SFT(지도 파인튜닝)와 정렬 학습(alignment training)의 차이는 무엇인가요?</b></summary>

| | SFT (지도 파인튜닝) | 정렬 학습 (선호도 최적화) |
|---|---|---|
| 학습 신호 | "이것이 정답이다" (모범 답변) | "이것이 저것보다 낫다" (비교·보상) |
| 데이터 | (프롬프트, 모범 응답) | (프롬프트, 선호 응답, 비선호 응답) 또는 보상 함수 |
| 방법 | 다음 토큰 예측 (모방 학습) | RLHF(PPO), DPO, GRPO, Constitutional AI 등 |
| 배우는 것 | 형식, 지시 따르기, 기본 행동 | 미묘한 품질 판단: 유용성, 정직성, 무해성, 어조 |
| 나쁜 행동 학습 | 직접적으로 배우지 않음 | 무엇이 나쁜 답인지도 학습 |
| 순서 | 먼저 | SFT 이후 |

**왜 둘 다 필요한가**

- SFT만으로는 모델이 "모범 답변을 흉내" 낼 뿐, 여러 그럴듯한 답 중 무엇이 더 나은지 구분하는 능력이 약합니다.
- 사람은 모범 답을 직접 쓰는 것보다 **비교 판단** 을 더 쉽고 일관되게 할 수 있어, 정렬 학습은 더 효율적으로 품질 신호를 얻습니다.
- 반대로 SFT 없이 바로 정렬 학습을 하면, 모델이 대화 형식조차 모르는 상태라 학습이 어렵습니다.

**"정렬(alignment)"의 넓은 의미**

- 모델의 행동을 사람의 의도와 가치에 맞추는 모든 과정을 말하며, 넓게 보면 SFT도 정렬 과정의 일부입니다.
- 면접에서는 보통 SFT 이후의 **선호도 기반 학습 단계** 를 "정렬 학습"이라고 구분해 설명합니다.

**더 읽어보기 (영문):** [Decoding InstructGPT](https://outcomeschool.com/blog/decoding-instructgpt)

<summary><b>Q24. RLAIF(RL from AI Feedback)란 무엇이며, RLHF와 어떻게 다른가요?</b></summary>

**RLAIF** 는 RLHF와 같은 구조를 쓰되, 응답 비교·평가를 **사람 대신 AI 모델(주로 강한 LLM)이 수행** 하는 방법입니다.

**과정**

1. 정책 모델이 같은 프롬프트에 대해 여러 응답을 생성합니다.
2. **AI 평가자** 가 원칙이나 기준(헌법, 채점 기준)을 바탕으로 어느 응답이 더 나은지 판단합니다.
3. 이 AI 선호 데이터로 보상 모델을 학습하거나(또는 AI 평가자를 직접 보상으로 사용), RL·DPO로 정책을 학습합니다.

**RLHF와 비교**

| | RLHF | RLAIF |
|---|---|---|
| 선호 판단 주체 | 사람 | AI 모델 |
| 비용·속도 | 비싸고 느림 | 싸고 빠름, 대규모 확장 가능 |
| 일관성 | 라벨러마다 편차 | 높음 (같은 기준 반복 적용) |
| 품질 상한 | 사람의 판단 | 평가 모델의 능력 |
| 편향 | 라벨러 편향 | 평가 모델의 편향(긴 답 선호, 자기 모델 선호 등) |
| 투명성 | 판단 근거 문서화가 어려움 | 원칙·프롬프트로 기준이 명시적 |

**연구 결과:** Google 연구(2023) 등에서 요약·대화 작업에서 RLAIF가 RLHF와 비슷한 수준의 결과를 낼 수 있다고 보고했습니다.

**실무 활용**

- 사람 피드백은 소량의 고품질 데이터와 평가 기준 수립, AI 평가자 검증에 쓰고, 대량 라벨링은 AI가 맡는 **혼합 방식** 이 일반적입니다.
- AI 평가자가 사람 판단과 얼마나 일치하는지 주기적으로 측정해야 합니다.

**관련:** Anthropic의 Constitutional AI는 RLAIF의 대표적인 구현입니다.

</details>

<summary><b>Q25. Constitutional AI란 무엇이며, RLHF와 어떻게 다른가요?</b></summary>

**Constitutional AI(CAI)** 는 Anthropic이 2022년 제안한 방법으로, 사람이 일일이 유해성 라벨을 다는 대신 **명시적인 원칙 목록("헌법")** 을 주고, 모델이 그 원칙에 따라 스스로 응답을 비평·수정하고 평가하게 해서 무해성을 학습시킵니다.

**두 단계**

1. **지도 학습 단계 (자기 비평과 수정)**
   - 모델이 유해할 수 있는 프롬프트에 응답을 생성합니다.
   - 헌법의 원칙 하나를 골라 "이 응답이 원칙에 어긋나는 점을 비평하라" → "비평을 반영해 응답을 수정하라"를 반복합니다.
   - 수정된 응답으로 SFT를 합니다.
2. **강화학습 단계 (RLAIF)**
   - 모델이 생성한 두 응답 중 어느 것이 원칙에 더 맞는지 **AI가 판단** 해 선호 데이터를 만듭니다.
   - 이 데이터로 선호 모델을 학습하고 RL로 정책을 최적화합니다.

**헌법의 예 (원칙 형태)**

- "가장 해롭지 않고 윤리적인 응답을 고르시오."
- "불법적이거나 위험한 활동을 돕는 내용이 적은 응답을 고르시오."

**RLHF와 비교**

| | RLHF | Constitutional AI |
|---|---|---|
| 무해성 피드백 | 사람 라벨러 | 원칙에 기반한 AI 피드백 |
| 기준의 투명성 | 라벨러 판단에 암묵적으로 존재 | 헌법으로 명시·수정 가능 |
| 확장성 | 사람 비용에 제한 | 대규모 확장 가능 |
| 회피적 거절 | 과잉 거절이 생기기 쉬움 | 해로운 요청에도 이유를 설명하며 응대하는 방향으로 개선 |
| 사람 역할 | 대량 라벨링 | 원칙 작성, 유용성 데이터, 검증 |

**의미:** 사람이 "어떤 가치를 따를지"를 원칙으로 명시하면, 그 적용은 AI가 대규모로 수행하는 구조입니다. 원칙을 바꾸면 행동을 조정할 수 있어 투명성과 통제력이 높아집니다.

</details>

<details>
<summary><b>Q26. RLVR(Reinforcement Learning with Verifiable Rewards)이란 무엇이며, 학습된 보상 모델보다 나은 경우는 언제인가요?</b></summary>

**RLVR** 은 사람 선호를 흉내 내는 보상 모델 대신, **자동으로 정답 여부를 확인할 수 있는 규칙 기반 보상** 으로 강화학습을 하는 방법입니다.

**검증 가능한 보상의 예**

- **수학:** 최종 답이 정답과 일치하면 1, 아니면 0
- **코드:** 단위 테스트를 모두 통과하면 1
- **형식:** 지정된 JSON 스키마·태그 구조를 지키면 보너스
- **논리 퍼즐, 제약 만족 문제:** 해답을 프로그램으로 검증
- **지시 준수:** "300자 이내", "키워드 3개 포함" 같은 검사 가능한 조건

**학습 방법:** 주로 GRPO 같은 알고리즘으로, 한 문제에 여러 답을 생성하고 맞힌 답을 강화합니다. 모델은 정답률을 높이는 과정에서 단계별 추론, 검산, 되돌아가기 같은 행동을 스스로 발전시킵니다(DeepSeek-R1 등 추론 모델의 핵심).

**학습된 보상 모델보다 나은 경우**

1. **정답이 명확하고 자동 검증이 가능한 작업:** 수학, 코딩, 논리, 구조화된 추출
2. **보상 해킹 방지가 중요할 때:** 보상 모델은 허점이 있어 정책이 이를 악용하지만, 규칙 기반 정답 검증은 속이기 어렵습니다(단, 테스트가 허술하면 테스트 자체를 속이는 꼼수가 생길 수 있음).
3. **대규모 학습:** 사람 라벨이나 보상 모델 추론 비용 없이 무한히 문제를 채점할 수 있습니다.
4. **사람보다 뛰어난 수준을 목표로 할 때:** 사람 선호는 사람의 판단 능력에 묶이지만, 정답 검증은 그렇지 않습니다.

**학습된 보상 모델이 필요한 경우:** 글쓰기 품질, 대화의 유용성, 어조, 안전성처럼 정답이 하나가 아니고 자동 검증이 어려운 작업. 실제로는 두 보상을 함께 쓰는 경우가 많습니다.

**더 읽어보기 (영문):** [Group Relative Policy Optimization (GRPO)](https://outcomeschool.com/blog/group-relative-policy-optimization-grpo)

</details>

<details>
<summary><b>Q27. 파인튜닝을 위한 지식 증류(knowledge distillation)란 무엇이며, 법적으로 고려할 점은 무엇인가요?</b></summary>

**파인튜닝 관점의 지식 증류** 는 강한 교사 모델(대형 LLM)의 출력이나 확률 분포를 학습 데이터로 삼아, 작은 학생 모델을 파인튜닝하는 것입니다.

**방식**

1. **응답 증류 (가장 흔함):** 교사 모델에 다양한 프롬프트를 주고 받은 답변·추론 과정을 SFT 데이터로 사용합니다. API 접근만으로 가능합니다.
2. **로짓 증류:** 교사의 토큰별 확률 분포를 KL 발산으로 따라 합니다. 교사 모델 가중치에 접근할 수 있고 토크나이저가 같아야 합니다.
3. **온폴리시 증류:** 학생이 생성한 답에 대해 교사가 토큰 단위로 교정합니다.

**활용:** 특정 작업에서 대형 모델 수준의 품질을 작고 싼 모델로 구현, 온디바이스 모델, 추론 모델의 사고 능력 이전.

**법적·정책적 고려 사항**

1. **이용 약관:** 많은 상용 LLM 제공사(OpenAI, Anthropic, Google 등)는 출력을 **경쟁 모델 개발에 사용하는 것을 약관으로 금지** 합니다. 사용 목적과 해당 제공사의 최신 약관을 반드시 확인해야 합니다.
2. **오픈 모델 라이선스:** 오픈 웨이트 모델도 라이선스마다 출력 사용 조건이 다릅니다. 예를 들어 일부 라이선스는 파생 모델 이름 표기나 사용 규모 제한 같은 조건을 둡니다. 증류 결과물의 배포 조건을 확인합니다.
3. **학습 데이터 저작권:** 교사 출력에 저작권이 있는 내용이 재현될 수 있습니다.
4. **개인정보:** 증류용 프롬프트에 고객 데이터를 넣으면 외부 API로 전송되는 것이므로 데이터 처리 계약·규정을 확인합니다.
5. **문서화:** 어떤 모델의 출력으로 학습했는지 기록해 감사와 법적 검토에 대비합니다.

**안전한 선택지:** 증류를 허용하는 라이선스의 오픈 모델을 교사로 쓰거나, 제공사가 공식 지원하는 증류 기능을 사용합니다. 법무팀 검토를 받는 것이 좋습니다.

**더 읽어보기 (영문):** [How does Knowledge Distillation work?](https://outcomeschool.com/blog/how-does-knowledge-distillation-work)

<summary><b>Q28. 학습 데이터 품질 문제 때문에 파인튜닝한 LLM이 사실과 다른 출력을 냅니다. 어떻게 고치나요?</b></summary>

**원인 파악**

- 학습 데이터에 **틀린 사실, 오래된 정보, 서로 모순된 예시** 가 있음
- 합성 데이터의 환각이 그대로 학습됨
- 모델이 원래 모르는 지식을 파인튜닝으로 억지로 넣으려 해서, "모르는 것도 자신 있게 말하는" 습관이 생김(새 지식을 SFT로 주입하면 환각이 늘어날 수 있다는 연구가 있음)
- 라벨러 간 기준이 달라 일관성이 없음

**해결 절차**

1. **오류 사례 역추적:** 틀린 출력과 비슷한 학습 예시를 검색(임베딩 유사도)해 원인이 된 데이터를 찾습니다.
2. **데이터 감사와 정제**
   - 사실 검증: 전문가 검토, 신뢰할 수 있는 출처와 대조, LLM 판정자로 1차 선별
   - 모순·중복 예시 제거, 오래된 정보 갱신
   - 라벨 가이드라인을 명확히 하고 라벨러 간 일치도 측정
   - 합성 데이터는 검증된 것만 사용
3. **지식은 RAG로 분리:** 사실 지식은 학습 데이터에서 빼고 검색으로 제공합니다. 파인튜닝은 "근거를 보고 답하는 법"과 형식·스타일에 집중합니다.
4. **불확실성 학습:** 답할 수 없는 경우 "모르겠습니다"로 답하는 예시를 포함합니다.
5. **재학습:** 정제된 데이터로 원래 기반 모델에서 다시 학습합니다(오염된 모델 위에 덧붙여 학습하기보다 깨끗하게).
6. **평가 강화:** 사실성 평가셋을 만들고 출시 전 기준으로 사용합니다.

**예방:** 데이터 수집 단계부터 품질 기준, 검수 단계, 출처 기록을 갖춘 데이터 파이프라인을 운영합니다.

<summary><b>Q29. 도메인 특화 어시스턴트를 위해 LoRA와 전체 파인튜닝 중 하나를 골라야 합니다. 어떻게 결정하나요?</b></summary>

**결정 기준**

| 기준 | LoRA 쪽 | 전체 파인튜닝 쪽 |
|---|---|---|
| 변화의 크기 | 형식·어조·작업 특화 (작은 변화) | 새 언어, 대규모 도메인 지식 흡수 (큰 변화) |
| 데이터 양 | 수백~수만 개 | 수십만 개 이상, 또는 대량 원문 |
| GPU 자원 | 제한적 (단일 GPU) | 다중 고급 GPU 가능 |
| 망각 위험 허용도 | 낮음 (일반 능력 유지 중요) | 감수 가능 |
| 여러 도메인·고객 | 어댑터를 교체하며 서빙 | 도메인마다 전체 모델 사본 |
| 반복 실험 | 빠르고 싸게 여러 번 | 느리고 비쌈 |

**실무 결정 과정**

1. **LoRA로 시작합니다.** 대부분의 도메인 어시스턴트는 LoRA로 충분하며, 비용·속도·운영 면에서 유리합니다.
2. **랭크와 대상 모듈을 늘려 봅니다.** 성능이 부족하면 랭크(16 → 64 → 128)와 적용 층(어텐션 → 전체 선형층)을 확장합니다.
3. **같은 평가셋으로 비교합니다.** 가능하다면 소규모로 전체 파인튜닝도 실험해 성능 차이와 비용 차이를 비교합니다.
4. **차이가 의미 있게 클 때만 전체 파인튜닝을 선택합니다.** 일반적으로 LoRA는 지시 튜닝 같은 작업에서 전체 파인튜닝과 차이가 작고, 대량의 새로운 지식 학습(지속 사전 학습 수준)에서 차이가 커지는 경향이 있습니다.

**함께 고려할 것**

- 사실 지식은 RAG로 제공하면 파인튜닝 부담이 줄어 LoRA로 충분해지는 경우가 많습니다.
- 서빙 환경이 멀티 LoRA를 지원하는지, 어댑터를 병합해 배포할지 결정합니다.

<summary><b>Q30. 파인튜닝한 모델이 패턴을 학습하지 않고 학습 데이터를 그대로 암기했습니다. 과적합을 어떻게 고치나요?</b></summary>

**증상**

- 학습 손실은 매우 낮은데 검증 손실은 오르거나 정체
- 학습 데이터와 비슷한 입력에 학습 답변을 문장 그대로 출력
- 표현을 조금 바꾼 입력에는 성능이 급격히 떨어짐
- 출력 다양성이 줄어듦

**원인:** 데이터가 적거나 다양성이 부족함, 에포크가 너무 많음, 학습률이 너무 높음, 중복 예시가 많음, 모델 용량(또는 LoRA 랭크)에 비해 데이터가 작음.

**해결책**

1. **학습 강도 줄이기**
   - 에포크 줄이기(보통 1~3), **조기 종료**(검증 손실 기준), 학습률 낮추기.
2. **데이터 개선 (가장 효과적)**
   - 데이터 양과 다양성 늘리기: 다양한 표현의 입력, 다른 상황의 예시.
   - 중복·거의 같은 예시 제거.
   - 데이터 증강: 입력을 바꿔 쓰기(paraphrase), 같은 의도를 다양한 방식으로 표현.
   - 일반 지시 데이터를 일부 섞기.
3. **정규화**
   - 가중치 감쇠, 드롭아웃(LoRA dropout).
   - LoRA 랭크 줄이기, 적용 모듈 줄이기.
   - NEFTune처럼 임베딩에 약간의 노이즈를 넣는 기법.
4. **손실 마스킹 확인**
   - 프롬프트 부분까지 손실에 포함하면 입력 자체를 외우는 경향이 커집니다. 응답 토큰에만 손실을 계산합니다.
5. **평가 방식 개선**
   - 학습 데이터와 겹치지 않는(표현이 다른) 검증·테스트셋으로 일반화 성능을 측정합니다.
   - 학습 데이터 문장이 그대로 재현되는 비율(n-gram 일치율)을 모니터링합니다.

<summary><b>Q31. 도메인 특화 파인튜닝 후 LLM이 일반적인 능력을 잊어버렸습니다. 파괴적 망각을 어떻게 고치나요?</b></summary>

**이미 망각이 생긴 경우의 복구 방법**

1. **데이터 혼합 후 재학습**
   - 원래 기반 모델에서 다시 시작해, 도메인 데이터에 **일반 지시 데이터(예: 10~30%)** 를 섞어 학습합니다. 가장 확실하고 일반적인 해결책입니다.
2. **학습 강도 낮추기**
   - 학습률과 에포크를 줄이고, 일반 벤치마크가 떨어지기 시작하는 지점 전에 멈춥니다.
3. **LoRA로 전환 또는 랭크 축소**
   - 전체 파인튜닝을 했다면 LoRA로 바꾸면 원래 가중치가 보존되어 망각이 크게 줄어듭니다.
4. **모델 병합**
   - 파인튜닝 모델과 원래 모델의 가중치를 보간합니다(`θ = λ·θ_ft + (1-λ)·θ_base`, WiSE-FT 방식). λ를 조절해 도메인 성능과 일반 능력의 균형점을 찾습니다. 재학습 없이 바로 시도할 수 있습니다.
5. **정규화 기법**
   - 원래 모델 출력과의 KL 제약, 중요한 가중치 변화에 페널티(EWC).
6. **구조적 분리**
   - 도메인 질문은 파인튜닝 모델(또는 LoRA 어댑터)로, 일반 질문은 원래 모델로 라우팅합니다. 어댑터 방식이면 요청에 따라 어댑터를 켜고 끕니다.

**재발 방지**

- 파인튜닝 전후 평가에 **일반 능력 벤치마크**(지시 따르기, 추론, 상식, 안전성)를 반드시 포함합니다.
- 학습 중 일정 간격으로 일반 벤치마크를 측정해 망각이 시작되는 시점을 파악합니다.

**더 읽어보기 (영문):** [Continual Learning in LLMs](https://outcomeschool.com/blog/continual-learning-in-llms)

<summary><b>Q32. RLHF 선호도 데이터의 라벨러 간 일치도가 낮습니다. 데이터 품질을 어떻게 보장하나요?</b></summary>

**먼저 원인을 구분합니다**

- **가이드라인이 모호함:** "더 좋은 답"의 기준이 정의되지 않음 (정확성 vs 간결성 vs 친절함)
- **과제 자체가 주관적:** 취향 차이가 큰 창작·어조 판단
- **두 응답의 품질이 실제로 비슷함:** 차이가 미미해 누구라도 헷갈림
- **라벨러 역량·집중도 문제:** 도메인 지식 부족, 대충 응답

**품질 보장 방법**

1. **가이드라인 개선**
   - 평가 기준과 **우선순위** 를 명시합니다(예: 안전성 > 정확성 > 유용성 > 어조).
   - 애매한 사례에 대한 판정 예시를 문서화하고, 정기적으로 갱신합니다.
2. **라벨러 교육과 검증**
   - 교육 후 정답이 정해진 **골드 문제** 로 자격 시험을 봅니다.
   - 작업 중에도 골드 문제를 섞어 정확도를 모니터링하고, 기준 미달 라벨러를 재교육하거나 제외합니다.
   - 도메인 작업(의료, 코드)은 전문가를 배정합니다.
3. **평가 형식 개선**
   - 단순 A/B 선택 대신 **기준별 점수**(정확성, 유용성 등)와 선택 이유를 함께 받습니다.
   - "비슷함/판단 불가" 선택지를 허용해 억지 선택으로 생기는 노이즈를 줄입니다.
   - 선호 강도(약간 낫다 / 훨씬 낫다)를 함께 받습니다.
4. **중복 라벨링과 집계**
   - 같은 쌍을 여러 명이 평가하고 다수결이나 라벨러 신뢰도 가중 집계를 합니다.
   - 불일치가 큰 사례는 전문가가 최종 판정합니다.
5. **데이터 필터링**
   - 일치도가 낮은 쌍은 학습에서 제외하거나 가중치를 낮춥니다. 품질 차이가 분명한 쌍이 학습에 더 유익합니다.
6. **지표 모니터링**
   - Cohen's/Fleiss' kappa, Krippendorff's alpha 같은 일치도 지표를 과제 유형별로 추적합니다.

**참고:** 어느 정도의 불일치는 사람 선호의 다양성 자체를 반영하므로, 0으로 만드는 것보다 **기준이 명확해야 하는 부분의 불일치를 줄이는 것** 이 목표입니다.
